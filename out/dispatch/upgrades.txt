GEMINI BILLING WAS RESTORED MID-RUN and the film was re-voiced on the standard path. The fallback repairs below still matter, because the next outage will find them already fixed.
scripts/vo_soundcheck.py leak gate was wrong and it failed all three Gemini takes. It reported the model had spoken the director's short-pause tag, which it never did. The check was a set intersection of tag words against heard words with no reference to the script, and line 6 of this film's own writing is "Fairbanks asked for a pause on both its state and federal lists". Any tag word that is also a real word in the writing failed every take however cleanly it was read. A leak is an EXCESS, not a presence, so it counts against the script now. Verified by simulation that a genuinely spoken tag still trips it.
scripts/reconform_to_voice.py is NEW. conform_storyboard.py maps a PLANNING clock onto a narration once, using per-beat line anchors or a planning_clock block it wrote itself, and today's board has neither, so there was no way to move the film onto a new take. This conforms clock to clock instead. Both takes speak the same nineteen lines, so a time inside old line i lands at the same fraction of new line i. Shots snap to their own sentence rather than being mapped, because a shot opening on the tail of the previous line is the defect say_it_show_it exists to catch. It also re-derives the run's hand-set beat invariants from what they mean, so they survive the next re-conform.
scripts/dispatch_vo_edge.py, the sanctioned fallback, could not run in this container at all. aiohttp does not read HTTPS_PROXY without trust_env, and outbound TLS is re-terminated by the agent proxy so the chain has to verify against the proxy CA. Either fault alone produced the same misleading complaint about a self-signed certificate in the chain.
scripts/dispatch_vo_edge.py called the playwright-bundled ffmpeg, which has no mp3 decoder, so it died on edge-tts output with exit 183 and a complaint about invalid data. That reads like a corrupt download and is not one. It now prefers a system ffmpeg that can decode.
